# Database and model conventions (all stacks)

- Table names: `tm_<name>` for masters, `tx_<name>` for transactions, `tl_<name>` for ledgers,
  `tc_<name>` for control/config, `ta_<name>` for audit/log. Snake_case, singular.
- NO database foreign keys and NO Django `ForeignKey`/`OneToOneField`/`ManyToManyField`.
  Store references as `<entity>_id` integer (or bigint) columns with an index. Relations are
  resolved in the service/selector layer; integrity is enforced in services inside a transaction.
- Every table has: `id` (bigint auto), `company_id` (bigint, indexed, NOT NULL except tc_*),
  `record_status` (char(1): A active, I inactive, D deleted), `created_by`, `created_at` (UTC),
  `updated_by`, `updated_at` (UTC). Transaction tables add `doc_no`, `doc_date` (date, company
  calendar), `fy_id`, `branch_id`, `status` (D draft, P posted, C cancelled), `posted_at`, `cancelled_at`.
- Soft delete only: set `record_status = 'D'`; never issue DELETE on tm_/tx_/tl_ rows. Every
  default query filters `record_status = 'A'`; drafts (`tx_` status D) may be hard-deleted by the
  owner only via a service method.
- `company_id` is injected by the server from the authenticated session/header and NEVER taken
  from the request body or query string. Every query includes `company_id`. Cross-company reads
  are a P1 defect.
- Money: DECIMAL(18,2). Quantity: DECIMAL(18,3). Rates/FX/percent: DECIMAL(18,4). Never FLOAT.
- Codes and document numbers: generated by a numbering service per company + branch + FY +
  series (`tc_doc_series`), inside the posting transaction, never by the client.
- Indexes: (company_id, record_status) on every table; (company_id, doc_date) on tx_; unique
  (company_id, code) on masters.
- MySQL/MariaDB: InnoDB, utf8mb4, `sql_mode=STRICT_TRANS_TABLES`. PostgreSQL: use `timestamptz`
  for timestamps; everything else identical so a product can switch DB without model changes.
- Migrations are reviewed by a human; an agent never runs a migration against staging or
  production and never edits a migration that is already applied there.
